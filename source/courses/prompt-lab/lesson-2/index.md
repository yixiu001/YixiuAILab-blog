上一节说过，提示词的问题通常是"信息没说全"。这一节给一个最简单的框架，把该说的信息固定下来：**角色、任务、约束、输出格式**。

### 一、四个要素分别是什么

- **角色**：让模型站在什么立场说话。决定语气、专业深度和看问题的角度。
- **任务**：具体要它做什么。用动词开头，一条任务写一句话。
- **约束**：边界条件——给谁看、多长、避免什么、必须包含什么。
- **输出格式**：清单、表格、分点、代码，还是一段可直接复制的文案。

{% note info 为什么是这四个 %}
角色决定"用什么口吻"，任务决定"做什么事"，约束决定"做到什么程度"，格式决定"怎么交付"。这四块补齐，绝大多数日常任务的输出就会从"看运气"变成"可预期"。
{% endnote %}

### 二、可以直接复制的模板

```
你是【角色】，擅长【领域】。

请完成以下任务：【一句话说清要做什么】。

要求：
- 面向【目标读者】
- 控制在【字数/条数】以内
- 不要【明确要避免的内容】
- 必须包含【关键信息】

请用【表格 / 分点清单 / 段落】的形式输出。
```

### 三、改写示例

假设你想让 AI 帮忙写一条新工具的推广文案。

**改写前**

> 帮我写个介绍 Notion 的文案。

**改写后**

> 你是一位面向效率工具领域的科技博主，语气轻松、不说套话。
>
> 请写一段介绍 Notion 的推广文案。
>
> 要求：
> - 面向没用过笔记工具的上班族
> - 控制在 200 字以内
> - 不要罗列功能参数
> - 必须包含一个"用它管理工作任务"的具体场景
>
> 请用一段正文 + 一句结尾行动号召的形式输出。

后一版不需要你再追问"能不能短一点""能不能具体点"——因为这些要求已经在第一轮里说清楚了。

### 四、什么时候不必写全

四要素是模板，不是教条。简单任务比如"把这段话翻译成英文"，只写任务就够。**判断标准很简单：如果结果不满意时你需要追加条件，那就把那个条件提前写进约束里。**

{% folding 模型还是会跑偏怎么办？ %}
先检查约束里有没有含糊词（"好看一点""专业一点"）。把它换成可判断的标准，比如"不超过 3 个层次""每段首句给出结论"。如果仍然跑偏，就直接把不满意的样例贴给它，说明"不要这种写法"。
{% endfolding %}
